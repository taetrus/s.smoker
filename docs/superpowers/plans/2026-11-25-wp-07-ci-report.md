# WP-07 CI Matrix and Report (code tasks) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pipeline with two jobs gets one report with the last 20 runs, stable run conditions, a release guard and a lint baseline.

**Architecture:** `run` writes a job summary (`job-result.json`); the new command `report --merge` reads the summaries and writes one overview page with links into the report of each job, and keeps a history file. The agent applies locale, time zone and look and feel in `premain` and the window size when the main window shows, and writes the actual values and warnings into the result. `check-release` and the lint baseline are CLI-only.

**Tech Stack:** Java 8 source level, Maven, JUnit 4, relocated Gson (`smoker.core.io.Json`). No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-25-wp-07-ci-report-design.md`. The spec wins where this plan and the spec differ.

## Global Constraints

- Java 8 source level: no `var`, `List.of`, `String.isBlank`, `Files.readString`. Compile with `--release 8`.
- No new dependency. JSON only through `smoker.core.io.Json`.
- All case conversion uses `Locale.ROOT`.
- Every Swing access goes through the EDT. Never wait on an action `Runnable` directly; wait for a later ping (`Quiescence.edtResponds`).
- `premain` must not load a Swing or AWT class (`javax.swing.*`, `java.awt.*`) for the new keys.
- `[smoker]` texts and all new CLI texts are ASCII.
- Old `run-result.json` files and old agent configuration files stay valid: each new field and key is optional.
- `.gitlab-ci.yml` does not change (task 4 of WP-07 is field phase).
- `report.html` of a result without warnings is the same as today, except for the new `id` attributes.
- A test that makes a `Recorder` calls `recorder.close()` in `@After`. A test leaves no showing window.
- Documents in Simplified Technical English. When a change alters a file format or a command, update `README.md` in the same commit.
- Commit messages start with `WP-07:` and name `F-18` and the requirement (R-41, R-42, R-34, R-40a). Never `git add -A`.
- Run `mvn -B verify` and `mvn -B verify -Plocale-tr` after every change to `smoker-agent` or `smoker-core`. One Maven build at a time, in the foreground. Focused runs: `-Dtest=<Class> -Dsurefire.failIfNoSpecifiedTests=false`; for one IT method add `-Dit.test=SelfTestIT#<method> -Dtest=NoSuch`.

## Review Focus

1. A scenario whose `name` differs from its file name, HANG in one job (no result file) and PASS in the other: one row in the merged page, one key in the history (Task 2, Task 3).
2. A job folder on another drive or with a blank in its path: the links of the merged page still open (Task 2).
3. An application that replaces the locale after `premain` (Equinox `-nl`): the result has a warning, the status does not change (Task 4).
4. A `history.json` that another program truncated: the report is written, the file is kept as `.damaged`, the page and `System.err` say so (Task 3).
5. `check-release` with two paths of which one has no `.ini` file: exit code 2, not 0 (Task 6).
