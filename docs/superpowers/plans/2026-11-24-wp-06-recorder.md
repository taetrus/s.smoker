# WP-06 Recorder (code tasks) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The recorder records and the player replays tree selection, the double-click, the right-click, a table cell edit and a spinner value; the toolbar gets a golden preview, step groups and a move function.

**Architecture:** Optional fields on `Action` (`count`, `button`, `row`, `column`, `path`) give the place in a component; the locator does not change. A new class `Places` holds the place rules (column, tree path, bounds) for the player and the recorder. `Recorder` gets the new event rules; `RecorderToolbar` gets a second pane and three buttons.

**Tech Stack:** Java 8 source level (`--release 8`), Swing, JUnit 4, Maven. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-24-wp-06-recorder-design.md`. Read it first. Section numbers below refer to it.

## Global Constraints

- Java 8 source level: no `var`, no `List.of`, no `String.isBlank`, no `Files.readString`, no lambdas where the file uses anonymous classes (follow the file).
- No new dependency. The agent does no bytecode instrumentation.
- Every Swing access goes through the EDT. Never wait on an action `Runnable` directly; use a later EDT task or `Quiescence`.
- All case conversion uses `Locale.ROOT`.
- Each window or dialog of the tool has a name that starts with `smoker.`.
- Never write the text of a `JPasswordField` to a scenario, a snapshot, a report or a log (F-19).
- `Locators.resolve` and `Locators.find` do not change (F-23). `Locator` does not change.
- `[smoker]` log texts, status texts and button texts added by this plan are ASCII.
- `schemaVersion` stays 2. Each new JSON field is optional. A scenario file of today loads and replays as before.
- A test must not leave a window that reports "showing". Tests with windows start with `Assume.assumeFalse(GraphicsEnvironment.isHeadless())`. Turn screenshots off in tests that do not check them.
- Run Maven only in the foreground. Never start a background job that outlives your turn. One Maven build at a time.
- After each change to `smoker-agent` or `smoker-core`: `mvn -B verify` and `mvn -B verify -Plocale-tr` pass.
- A change to the scenario or golden format updates `README.md` and the demo scenarios in the same commit.
- Documentation is in Simplified Technical English: short sentences, active voice, one term for one thing.
- Commit messages start with `WP-06:` and name the finding or requirement (F-13, F-21, R-20a). Commit with the repository email (`git config --local user.email`). Never `git add -A`; add files by name.
- Error texts, exact: `tree node not found: <labels joined with />`, `column not found: <column>`, `row not found: <row>`, `the cell editor refused the value "<value>"`.

## Review Focus

1. **A table with a row sorter or moved columns.** `row` and the column index are view indexes. The cell edit reads and writes through `getValueAt(viewRow, viewColumn)`. Test in Task 3.
2. **A cell edit that a click on a button ends.** `SET_CELL` comes before the `CLICK` step, and the golden of `SET_CELL` shows the state before the button action. Test in Task 6.
3. **A combo box or check box as cell editor.** No `SELECT` on the editor combo, no `CLICK` on the editor check box; one `SET_CELL`. Test in Task 6.
4. **Two tree nodes with the same label under one parent.** Replay takes the first; no exception. Test in Task 2.
5. **A second click that is not a double-click of the last step** (another step came between, or the place is different). The recorder adds a step and changes no earlier step. Test in Task 5.

### Task 4: Recorder: in-place change of a step, move, group

This task has no event rules. It gives the step operations that Tasks 5, 7 and 8 use.

**Files:**
- Modify: `smoker-agent/src/main/java/smoker/agent/Recorder.java`
- Test: `smoker-agent/src/test/java/smoker/agent/RecorderStepsTest.java` (new)

**Interfaces:**
- Produces, in `Recorder` (all on the EDT):
  - `void changed(Step s)`: the action of `s` changed in place. Sets `s.name = s.action.toString()` when the name was the old default name, removes its snapshot, makes it pending again, calls `listener.stepUpdated(s)`.
  - `void move(Step s, int delta)`: `delta` is -1 or +1; no effect at the list border. Swaps `s` with its neighbour in `scenario.steps`. Removes the golden and the pending state of both, and marks both "golden removed". Then removes the golden of each step that is now directly before a `WAIT_FOR` step. Calls `stepUpdated` for each changed step.
  - `boolean goldenRemoved(Step s)`: true after a move removed its golden, until the step gets a snapshot again (it does not in this session, but `changed` clears the mark).
  - `void setGroup(Step s, String group)`: trims; an empty or null text sets `s.group = null`; calls `stepUpdated`.
  - `Snapshot previousSnapshot(Step s)`: the snapshot of the nearest earlier step in `scenario.steps` that has one, or null.
- Quiet rule (spec 6, "Events"): the snapshot thread must not take the snapshot of a step that `changed` made pending again on the strength of a quiet wait that started before the change. Use a change counter per step: `snapshotLoop` reads it before `Quiescence.await` and takes the snapshot only when it is the same in the EDT task; otherwise the step stays pending and the loop runs again.
